# 实际安装：Router 未激活与设置页 404

## 现场证据

用户会话 session-a534baa0-2a6f-4b10-8365-38a044d3de11 已记录 dsh-superagent-router。Plugin Manager 的 include:dsh-superagent fiberPhase=failed，diagnostic=`$.stateDir missing required value`；GitHub 来源 pending waiting for orchestrator。当前 Web `/superagent-status` 与 `/orchestrator/api/state` 均返回 404。

## 根因与修复

1. bundle row 只有插件名，没有 stateDir；schema 将其设为 required，Host 连轻量状态接口也无法创建。默认目录改为 `<DSH_PROFILE_DIR>/superagent`，未选预设时不创建状态目录、不启动后台服务。
2. 动态 Runtime 子插件没有声明 inject，真实 Cordis 报 `cannot get property subprocess without inject`。子插件现在声明与 Host 相同的依赖。
3. UI 状态接口失败时仍渲染 App 导致伪“重启中”提示；配置页依赖尚未存在的管理接口。改为独立状态诊断和可写 stateDir 配置入口。
4. 重复的打开主会话按钮没有处理 Promise rejection，移除重复按钮，使用已有 App header 的错误处理。

新增未 mock Runtime 的真实 Cordis 首次安装组合回归：空配置解析、Router 工具注册、状态 HTTP 200、未配置 GitHub 的 settings HTTP 200（repositoryUnset）。测试服务替身隔离模型/网络，不冒充真实安装 E2E。

## 应用边界

安装包链接当前工作树。尝试安装返回 already-installed；通过受支持的 Plugin Manager 关闭/重新启用目标插件，最终仍启用，管理器返回 restart-required / unmanaged-plugin。未杀进程或重启用户 DSH，未手改 profile 文件，未修改会话历史。管理器曾报告需要重启；随后运行态检查发现 Host 已 active，两个接口均 HTTP 200，等待 repositoryUnset 配置。不能仅凭 restart-required 推断模块始终未重载，以实际 HTTP 结果为准。

现场还发现空部署绑定了用户后来创建的另一个 Router，而非本次指定会话。新增同源管理 POST /superagent-status（仅允许 `{sessionId}`）：校验目标为真实 root Router，仅无任何 Tickets 的部署可显式转交；有工作记录则拒绝。转交串行并释放旧会话注册，不自动在多个会话间抢占。未配置仓库时可用它修复空部署的误绑定；请求需用户明确指定目标会话。
